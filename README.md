# Meta Pixel & Conversions API (CAPI) Deduplication Protocol

This repository outlines the technical architecture for implementing Meta's Conversions API (CAPI) alongside the browser Meta Pixel to ensure 100% accurate attribution without duplicate conversion reporting.

---

## 1. The Core Problem: Redundant Reporting
When tracking purchases via both the browser (Meta Pixel) and server (Conversions API), Meta receives two separate signals for a single order. Without proper deduplication:
* Reported ROAS is artificially doubled.
* The algorithm trains on duplicate signals, distorting bidding efficiency.

---

## 2. The Solution: `event_id` Deduplication
Meta uses two parameters to deduplicate events:
1. `event_name` (e.g., `Purchase`)
2. `event_id` (a unique transaction ID generated by the server, such as Order ID `#1042`)

### Browser Payload (JavaScript)
```javascript
fbq('track', 'Purchase', {
  value: 120.00,
  currency: 'USD',
  content_type: 'product'
}, { eventID: 'order_1042' });
